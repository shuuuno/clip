# Clip 0.6.0 UI 검토

2026-11-06. 대상은 캡처·주석 편집·MP4 녹화·영상/GIF 보기·라이브러리·설정이다. 기존 다크·파랑과 Windows 기본 글꼴을 유지하고 새 의존성은 추가하지 않았다.

스킬의 12·14·18·24·31·32 항목을 실제 렌더와 대조했다. 기존 단색 다크 배경, 파랑, Windows 글꼴, 기능별 선 아이콘, 실제 불리언 설정을 나타내는 스위치는 의도와 기능이 명확해 유지했다. 새 장식·브랜드색·의존성은 없다. 수동 점검에서 텍스트 입력창 하단 잘림과 선택 도구 오른쪽 1픽셀 잘림도 고쳤다.

## 검증 방법

- `scripts/build.ps1`, `scripts/test.ps1`, `scripts/publish.ps1`가 기존 진입점이다.
- `scripts/qa-ui-review.py`는 격리된 데이터로 빈 화면·설정 오류·설정 재열기·도구 단축키·한글 주석·최소 창·영상·GIF·캡처·녹화 화면과 접근성 정보를 기록한다.
- 녹화창은 제품에서 화면 캡처를 차단한다. 전후 비교 촬영에는 테스트 실행 파일의 `--ui-review-app --data-dir <폴더>` 호스트를 사용했다. 같은 제품 어셈블리를 실행하며 테스트 프로세스 안에서만 녹화창 캡처 제외를 해제한다. 실제 배포본 회귀 검사는 일반 Clip.exe로 수행한다.
- 화면은 Windows 11, 3840×2160, DPI 168(175%), 기본 1220×800 DIP와 최소 960×640 DIP에서 비교한다. 합성 이미지·영상·전체 화면 fixture를 사용한다. 한글은 Unicode 입력 검사이며 실제 IME 조합 시험과 구분한다.
- Windows 화면 제어 플러그인은 native pipe 연결 실패로 사용할 수 없었다. 프로젝트에 이미 있는 Python UI 검증 환경을 사용했다. 패키지를 새로 설치하지 않았다.
- kill-ai-slop 기본 스캐너는 C#/XAML을 지원하지 않는다. 전후 모두 검사 파일 0개이므로 결과를 UI 무결성이나 개선량의 근거로 삼지 않았다. 수정 판단은 WPF 소스와 실제 렌더를 대조한 결과다.

## 결과와 증거

전후 비교 페이지는 `artifacts/ui/Clip-0.6.0-전후비교.html`이며 화면별 원본 PNG와 접근성 JSON도 같은 폴더 아래에 있다. 최종 통과 수와 배포 검증 결과는 [검증 기록](acceptance.md)의 0.6.0 항목에 기록한다.

다른 노트북·Windows 10·혼합 DPI·다중 모니터·HDR·장시간 녹화 실기는 확인하지 않았다. GitHub 업로드·push·Release 생성은 수행하지 않는다.
